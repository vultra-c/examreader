## 系统架构总览

本系统实现 Android 手机与小米手环（Vela 平台）之间的双向数据交换。

```
┌──────────────────────┐         蓝牙通道          ┌──────────────────────┐
│   Android 手机端      │    ◄── XMS Wearable ──►   │   小米手环 Vela 端    │
│                      │    ◄── SDK + IPC ──►      │                      │
│  WearableManager     │                           │  interconn.js        │
│  ├─ NodeApi          │    JSON 消息（tag 路由）   │  ├─ interconnfile.js  │
│  ├─ AuthApi          │    ┌──────────────┐      │  └─ interconnTree.js  │
│  └─ MessageApi       │◄──►│ tag="file"   │◄────►│                      │
│                      │    │ tag="tree"   │      │  dataManager.js      │
│  TxtTransferHandler  │    └──────────────┘      │  ├─ storage API      │
│  TreeSyncHandler     │                           │  └─ 文件树/分页      │
│  MainActivity        │                           │  pages/push.ux       │
└──────────────────────┘                           └──────────────────────┘
```

## 第一部分：Android 手机端

### 1.1 SDK 集成

使用小米官方 **XMS Wearable SDK**（`xms-wearable-lib_1.4_release.aar`），提供三个核心 API：

- **NodeApi** — 设备发现、启动手环应用
- **AuthApi** — 权限检查与请求
- **MessageApi** — 双向消息收发

SDK 通过 IPC 与小米穿戴/小米运动健康通信，需要在 `AndroidManifest.xml` 中声明 `<queries>` 指定包名 `com.xiaomi.wearable` 和 `com.mi.health`。

### 1.2 连接流程（注册失败的三大致命陷阱）

连接必须严格按照以下顺序执行，任何跳步或遗漏都会导致"注册失败"：

```
connect()
  │
  ├── 1. removeListener(oldNode)     ← 先清理旧监听器（必须先置空 currentNode）
  ├── 2. getConnectedNodes()         ← 发现设备，拿到 Node.id
  ├── 3. checkPermissions()          ← 检查 DEVICE_MANAGER 和 NOTIFY 权限
  │       └── 缺权限时 requestPermission()，无论成功失败都继续
  ├── 4. launchWearApp(nodeId, "/pages/index")  ← 启动手环快应用
  │       └── 失败也继续（应用可能已在运行）
  └── 5. messageApi.addListener(nodeId, listener)
          ├── onSuccess → 连接成功
          └── onFailure
                ├── 消息包含 "You have registered" → 视为成功（监听器仍在工作）
                └── 其他错误 → 真正失败
```

**陷阱 1**：不调用 `launchWearApp` 直接 `addListener` → 失败。手环快应用必须先启动。

**陷阱 2**：`addListener` 返回 "You have registered" 时当作错误 → 实际上监听器已注册成功。App 退出再打开时必然触发。

**陷阱 3**：重连时不先 `removeListener` → 旧监听器占着位，新监听器永远注册不上。必须先置空 `currentNode`，再异步 `removeListener`，否则有竞态。

### 1.3 线程安全

`onMessageReceived` 在 SDK 后台线程调用，UI 线程也会读写消息处理器表。必须使用 **`ConcurrentHashMap<String, MessageCallback>`** 存储消息处理器，避免 `ConcurrentModificationException`。所有 UI 回调通过 `Handler.post()` 切回主线程。

### 1.4 消息路由

所有消息都是 JSON 字符串，通过 `tag` 字段路由：

```json
{"tag": "file", "stat": "startTransfer", "filename": "test", ...}
{"tag": "tree", "action": "getTree"}
```

`WearableManager` 收到消息后解析 `tag`，分发到对应的 `MessageCallback`。`TxtTransferHandler` 注册 `tag="file"`，`TreeSyncHandler` 注册 `tag="tree"`。

### 1.5 分片传输协议

TXT 文件按 **8000 字符/片** 分片，采用请求-确认模式：

```
手机端                              手环端
  │                                   │
  ├── startTransfer {filename, folder} ──►
  │                                   │
  │◄── ready {count} ──────────────────┤
  │                                   │
  ├── data {chunkNum: 0, content} ─────►
  │                                   │
  │◄── next_chunk ─────────────────────┤
  │                                   │
  ├── data {chunkNum: 1, content} ─────►
  │                                   │
  │◄── chapter_chunk_complete ─────────┤
  │                                   │
  ├── chapter_complete ────────────────►
  │                                   │
  │◄── chapter_saved ───────────────────┤
  │                                   │
  ├── transfer_complete ───────────────►
  │                                   │
  │◄── transfer_finished ──────────────┤
```

每一步都有 **15 秒超时**，超时后发送 `cancel` 消息并通知 UI。

### 1.6 文件树同步协议

```
手机端                              手环端
  │                                   │
  ├── {tag:"tree", action:"getTree"} ──►
  │◄── {response:"treeData", tree:[...]} ┤
  │                                   │
  ├── {tag:"tree", action:"createFolder", name, parentId} ──►
  │◄── {response:"folderCreated", folderId, success} ─────────┤
  │                                   │
  ├── {tag:"tree", action:"deleteNode", nodeId} ──►
  │◄── {response:"nodeDeleted", success} ──────────┤
  │                                   │
  ├── {tag:"tree", action:"moveNode", nodeId, direction} ──►
  │◄── {response:"nodeMoved", success} ────────────┤
```

树节点结构：`{id, name, type: "folder"|"content", children: [...]}`。蓝牙创建的节点 ID 以 `bt_` 开头（`bt_folder_xxx` 为文件夹，`bt_xxx` 为文件）。

### 1.7 UI 架构

- 主题：`Theme.Material.Light.NoActionBar` + 自定义渐变标题栏
- 布局：`ScrollView` → 纵向 `LinearLayout`，卡片式设计
- 状态栏：根据连接状态切换背景 drawable（绿色=已连接，橙色=连接中，红色=错误）
- 文件树：动态 `LinearLayout`（不用 RecyclerView），缩进表示层级
- 按钮：selector drawable 实现按压/禁用态反馈

## 第二部分：小米 Vela 手环端

### 2.1 通信架构

Vela 快应用使用 `@system.interconnect` 的 `instance()` 获取连接对象，通过 `onmessage` 接收消息。

核心设计：**interconn.js 封装器** + **interconnModule 模式**：

```javascript
// interconn.js：全局连接管理
globalThis.conn = new interconn();
// 注册模块
globalThis.connfile = globalThis.conn.register(interconnfile);
globalThis.conntree = globalThis.conn.register(interconnTree);
```

`register()` 方法将模块的 `name`（静态属性）作为 tag，自动绑定 `send` 和 `addListener`。模块收到消息时 `tag` 已被剥离，只剩业务字段。

### 2.2 数据存储

使用 `@system.storage` API，以 JSON 字符串形式存储。所有蓝牙传输内容存在一个键 `KD_BT_CONTENT` 下，数据结构为数组：

```json
[
  {"id": "bt_folder_123", "name": "新建文件夹", "type": "folder", "parentId": "bt_root"},
  {"id": "bt_456", "name": "考点1", "type": "content", "content": "...", "folder": "bt_root"}
]
```

内存缓存（`_btContentCache`）避免重复读 storage，写入时同步更新缓存。

### 2.3 分页阅读

手环屏幕 **336×480px**，文字区域 296px 宽。每行 **11 个汉字**，每页 **15 行**，即每页约 165 字。超长行自动折行，空行占一行。

### 2.4 页面结构

- `pages/index` — 主页，显示根级文件夹和文件列表
- `pages/subfolder` — 子文件夹浏览
- `pages/reader` — 阅读器，支持翻页
- `pages/push` — 蓝牙传输状态页（等待→连接→接收→成功/失败）
- `pages/search` — 搜索
- `pages/globalSettings` — 全局设置
- `pages/deleteConfirm` — 删除确认

`push.ux` 通过 `globalThis.connfile.setCallback` 接收传输回调，更新状态机。

### 2.5 manifest.json 关键配置

```json
{
  "features": [
    {"name": "system.interconnect"},
    {"name": "system.storage"},
    {"name": "system.file"}
  ],
  "config": {"designWidth": 336}
}
```

## 第三部分：协议规范汇总

### 消息格式

所有消息为 UTF-8 JSON 字符串，顶层必须包含 `tag` 字段：

| tag | 用途 | 方向 |
|-----|------|------|
| `file` | TXT 文件传输 | 双向 |
| `tree` | 文件树同步 | 双向 |

### file 消息（手机→手环，stat 字段路由）

| stat | 字段 | 说明 |
|------|------|------|
| `startTransfer` | filename, total, wordCount, startFrom, folder | 开始传输 |
| `d` | count, data(JSON字符串) | 数据分片 |
| `chapter_complete` | count | 章节分片发完 |
| `transfer_complete` | — | 全部发完 |
| `cancel` | — | 取消 |

### file 消息（手环→手机，type 字段路由）

| type | 字段 | 说明 |
|------|------|------|
| `ready` | count, usage | 手环就绪 |
| `next_chunk` | — | 请求下一片 |
| `chapter_chunk_complete` | — | 章节分片接收完 |
| `chapter_saved` | count, syncedCount, totalCount, progress | 章节已保存 |
| `transfer_finished` | — | 全部完成 |
| `error` | message, count | 错误 |
| `cancel` | — | 取消 |

### tree 消息（手机→手环，action 字段路由）

| action | 字段 | 说明 |
|--------|------|------|
| `getTree` | — | 请求文件树 |
| `createFolder` | name, parentId | 创建文件夹 |
| `deleteNode` | nodeId | 删除节点 |
| `moveNode` | nodeId, direction(`up`/`down`) | 调整同级显示顺序（手环列表按元数据数组顺序展示） |

### tree 消息（手环→手机，response 字段路由）

| response | 字段 | 说明 |
|----------|------|------|
| `treeData` | tree(JSONArray) | 文件树数据 |
| `folderCreated` | folderId, success, error | 创建结果 |
| `nodeDeleted` | success, error | 删除结果 |
| `nodeMoved` | success, error | 顺序调整结果 |

### data 分片内层 JSON

```json
{
  "index": 0,
  "name": "文件名",
  "content": "分片内容...",
  "wordCount": 12345,
  "chunkNum": 0,
  "totalChunks": 5
}
```

注意：`data` 字段的值是 **JSON 字符串**（二次编码），不是 JSON 对象。

## 第四部分：构建方式

### Android APK（无 Gradle）

```bash
# 1. 提取 AAR 中的 classes.jar
unzip xms-wearable-lib_1.4_release.aar -d aar-extract
cp aar-extract/classes.jar libs/wearable-sdk.jar

# 2. 编译资源
aapt2 compile --dir src/main/res -o build/res_compiled.zip

# 3. 链接资源
aapt2 link -I $ANDROID_JAR \
  --manifest src/main/AndroidManifest.xml \
  -o build/base.apk --java build/gen \
  -R build/res_compiled.zip --auto-add-overlay \
  --min-sdk-version 26 --target-sdk-version 28

# 4. 编译 Java
javac -source 1.8 -target 1.8 \
  -classpath "libs/wearable-sdk.jar:$ANDROID_JAR" \
  -d build/obj src/main/java/**/*.java build/gen/**/*.java

# 5. DEX（d8 支持 lambda desugar）
d8 --output build --lib $ANDROID_JAR --min-api 26 \
  build/obj/**/*.class libs/wearable-sdk.jar

# 6. 打包 + 对齐 + 签名
cd build && zip -j base.apk classes.dex
zipalign -f 4 base.apk aligned.apk
apksigner sign --ks debug.keystore --ks-pass pass:android \
  --v1-signing-enabled true --v2-signing-enabled true \
  --out 考点传输.apk aligned.apk
```

### Vela 快应用

使用 Vela IDE 打包，或使用 `hap` 命令行工具构建 `.rpx` 包。

## 总结

本系统的核心在于：

1. **连接顺序不可省略**：`removeListener` → `getConnectedNodes` → `checkPermissions` → `launchWearApp` → `addListener`
2. **"已注册"不是错误**：`addListener` 返回 "You have registered" 时视为连接成功
3. **线程安全**：`ConcurrentHashMap` + `Handler.post()`
4. **消息路由**：JSON `tag` 字段分发到不同处理器
5. **分片确认**：每发一片等手环回复 `next_chunk` 再发下一片
6. **二次编码**：`data` 字段是 JSON 字符串而非对象
7. **内存缓存**：Vela 端 storage 读取后缓存到内存，避免重复 I/O
